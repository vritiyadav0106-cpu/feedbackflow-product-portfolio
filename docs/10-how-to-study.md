# 10 — How to Study (Learning Plan)

This is a **study system**, not a one-time read. APM interviews test how you *think*, not what you memorized last night.

---

## Study principles

1. **Product before code** — Always read docs before `app.js`
2. **Teach back** — Explain each doc to an imaginary interviewer
3. **Write in your voice** — Add your real examples in `PERSONALIZE.md` and portfolio bio
4. **Time-box** — 45–60 min blocks with 10 min breaks
5. **Spaced repetition** — Review pitch on day 1, 3, 7, 14

## How to read each document

### First pass (understanding)

1. Skim headers — what is the doc's job?
2. Read fully — highlight **decisions** (not facts)
3. Close the doc — write 3 bullet summary from memory
4. Re-open — fix gaps

### Second pass (ownership)

1. Change one example to **your** experience
2. Find one thing you'd **disagree** with — practice defending or revising
3. Link doc to a **user story** and **metric**

### Third pass (interview)

1. Set 3-minute timer
2. Explain doc aloud without looking
3. Answer one "skeptical stakeholder" challenge

|-------|---------------|-----|

You do **not** need a CS degree. You need **structured product language**.

## Self-test questions

Answer without looking:

1. Who is Priya and what is her Monday problem?
2. What is the RICE formula?
3. Name 3 MVP non-goals and why.
4. What is the north star metric?
5. What ships in v1.1 vs v2?
6. Why localStorage instead of a database?
7. Walk through promote-to-feature flow.
8. What would you do differently?

**Score:** 6+/8 = interview ready on content. Below 6 = re-read specific docs.
